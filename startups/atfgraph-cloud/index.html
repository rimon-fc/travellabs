big words, simple jobs

A place to work. A memory. An alarm clock.

An agent is an AI program that does a job for you. Some jobs take days, and most agents forget everything while they wait. ATFGraph gives an agent three things so it does not.

We handle running it.

Put your agents somewhere that is looked after. Keep your mind on the work you want them to do.

It remembers its progress.

Finished steps are saved, along with what is needed to carry on, even after an interruption.

It can wait until later.

Pause for hours, days or months. Carry on when a timer goes off, an update arrives or a person replies.

work happens over time

Monday's request. Thursday's approval. The same job, continued.

An invoice agent checks a request, saves its progress and waits for a manager. When the manager approves, it wakes up and sends the approved payment instruction.

ReceiveAn invoice arrives.
Check & saveRecord what has passed.
WaitKeep progress while paused.
WakeA person approves.
ContinueSend the instruction.
Waiting is part of the job.The progress is kept without keeping the whole agent program running.
Approval becomes an event.The person's reply tells the waiting agent it can carry on.

try it by hand

Your first agent says hello.

This agent has two abilities. One shouts. The other greets someone and asks the first one to shout for it.

Write the agent

This is the whole thing. The two lines starting with @ tell ATFGraph what the agent can do.

hello/agent.py
from pydantic import BaseModel
from atfgraph import Agent

app = Agent(node_id="hello", version="1.0.0",
            description="Greets travellers")

class Greeting(BaseModel):
    greeting: str
    shouted: str
    length: int

@app.skill()
def shout(text: str) -> dict:
    return {"text": text.upper()}

@app.traversal()
async def greet(name: str, punctuation: str = "!") -> Greeting:
    loud = await app.traverse("hello.shout", text=f"hello {name}")
    return Greeting(greeting=f"Hello {name}{punctuation}",
                    shouted=loud["text"], length=len(name))

emitter compute, explained

Something changes. The right agents wake up.

An update arrives. A deadline passes. An approval is given. ATFGraph connects that signal to the agents waiting for it. When many agents need the same update, one check can tell them all, so they do not each have to keep asking.

  • Wake on a schedule, an incoming update or a condition.
  • Share permitted checks across the agents that care.
  • Resume only the work that needs to move forward.
saved progress, deliberate recovery

An interruption does not have to mean starting over.

Finished steps stay recorded. A stopped run resumes from its save, follows your rules for trying again, and takes extra care with actions that must not happen twice.

Keep the work already done. Know what still needs doing.

ATFGraph keeps a record of every run, so a team can see where a job stopped and how it carried on.

  • Save finished steps and what is needed next.
  • Set rules for retries and failed steps.
  • Run separate jobs side by side, and wait when one needs another.
  • Bring in a person when something needs judgement.
autonomy with oversight

Give agents responsibility. Keep people in control.

See what an agent would do before you let it do more. Review results, pause for decisions and follow the history of each run.

pricing

Pay when it works. Not while it waits.

The open-source project is the whole engine and it stays free. ATFGraph Cloud is the same engine with someone looking after it.

Why is waiting free?An agent may wait days for a reply. Charging for that would punish the exact thing ATFGraph is for.
Why pay per step?A step is one piece of work an agent does. More work done means more value, so that is what you pay for.
Why pay per person?Each person gets sign-in, approvals and a view of every job. That part costs the same however busy the agents are.
